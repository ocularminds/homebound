# FL-027 — Owner-published policy versions could drift from the home binding

- **Date:** 2026-10-02
- **Component:** HomeBound home-to-org policy version lifecycle
- **Environment:** Live Decionis Protocol read APIs; ignored local home binding
- **Expected:** When an owner publishes a policy revision in the Decionis workspace, HomeBound can record which active org policy version is associated with the home. The policy remains org-scoped; this record is not an independent per-home policy.
- **Observed:** Phase 7 stored the initial `homebound-household-v1` reference only. The AgentSafe package cannot request a specific policy version or return the evaluated bundle version, so an owner-published revision would leave the local home reference stale. The first direct script invocation also failed to resolve the local `scripts` package; running it as a module worked, then the direct CLI path was fixed.
- **Error:** No local workflow read the active Protocol bundle or tracked revisions for a home. Initial direct invocation returned `ModuleNotFoundError: No module named 'scripts'`.
- **Impact:** HomeBound could not show which active Decionis workspace version was associated with the local home after an owner edit.
- **Investigation:** Read Decionis Protocol's decision-register and policy-bundle contracts. The decision register reports the same active bundle selection used by evaluation; the bundle list provides its full rule set. A live read confirmed the register's active id/version matched the bundle list and the current HomeBound binding. Python sets `sys.path[0]` to the script directory when invoked by filename, so the project root must be available before local namespace-package imports.
- **Workaround:** Added a dry-run and explicit `--apply` sync command. It reads the decision register before and after the bundle list, verifies organization and active-bundle consistency, requires all five HomeBound rule IDs, and atomically updates the owner-only local binding with an append-only history of org policy versions associated with the home. This history does not create per-home policy copies. The immutable seed publisher preserves an already-synchronized owner version.
- **Resolution:** The live preview matched `homebound-household-v1`; applying it recorded the initial version in the ignored `.homebound/policy-binding.json`. Direct invocation now resolves local modules and succeeds. The command does not write or publish any Decionis policy.
- **Upstream/documentation gap:** AgentSafe does not expose a requested policy-version selector or selected policy version in its action contract. HomeBound can follow the active org policy but cannot prove which version an individual action used until that capability exists.
- **Status:** Resolved for local active-version tracking. Workspace creation and the real Presence approval ceremony remain separate phases.
